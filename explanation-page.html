Technical Explanation

✦

The project consists of four HTML files which are all linked to a single CSS stylesheet file. Having a centralised stylesheet for all pages of the project makes it much easier to manage the visual appeal and usability of the HTML files as a cohesive website.

All images and videos on the stop pages are wrapped in `figure` with `figcaption` providing a brief explanation and crediting the source, all of which are myself.

HTML entities were heavily utilised to great effect, allowing for certain characters to be displayed simply as text and not as code. Such as & or arrow symbols.

CSS naming convention used was kebab-case. It's very easy to read and code with. Sometimes I'd add a double underscore to specify certain things, as I was getting some overwhelm when giving elemnts classes. The @import at the top of stylesheet.css loads in Lora for body text and Playfair Display for headings.

semantic HTML elements are used throughout the project to make it more readable and structured than simply using `div` for everything. `strong` is used for importance rather than `b` and `em` for stress emphasis rather than `i`

The .css file uses custom properties that are defined using ': root' to easily create a cohesive aesthetic across colours, fonts and various spacing related stylings. The navigation bar and footer use CSS Flexbox. 'clamp-()' is applied to headings to make sure writing scales properly so that media doesn't need as much adjustment.

Breakpoints were utilised at 768px by 480px to ensure the webpages are accessible on smaller screens and mobile.

JavaScript

✦

The whole of main.js is broken down into three different init functions: initMap(), initQuiz() and initTool(). Each gets called at the bottom when the page is loaded using DOMContentLoaded. Each function checks what key elements are existing within the page before actually doing anything, which allows the single file to be on every page without throwing errors.

Shared data has a STOPS array which holds an object for each of the four stops, with info such as name, page link, a blurb and distance. For initMap there are SVG markers in index.html which each have the attribute data-stop with a number. The function grabs all of them with querySelectorAll, then loops through them and attaches click event listeners. When clicked, it reads the stop ID from data-stop then finds the matching object in the STOPS array using the function find(). Finally it puts the details into the info panel below the map using textContent and href for assignment.

For initQuiz the questions are stored as an array of objects. Each has the question text, an options array, the index of the right answer and two different strings for feedback, one correct one incorrect. When it loads, the array shuffles using a Fisher-Yates shuffle to randomly swap around the elements, making the order different each time. renderQuestion() reads the current question object to then make a <button> for each option using createElement, which sets text and attaches a click listener.

initTool has two data objects that sit outside the function. PACE_DATA maps each pace option and the stop objects give approximate distances between locations. The checkbox list is built by looping over the STOPS array and using createElement to generate each list item. The calories calculation uses the MET formula (MET × weight × time in hours).
